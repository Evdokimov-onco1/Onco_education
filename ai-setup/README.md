# ai-setup — настройка Claude, Cursor и Devin

Настраивается **один раз на машину**, работает во **всех** репозиториях.

## Это не рабочая папка

Сюда никогда не коммитится код проектов. Проекты живут в своих репозиториях,
а связь с ними — не git, а симлинк в домашней папке:

```
~/ai-setup/                  ← этот репозиторий. Здесь коммитятся ТОЛЬКО правила
~/code/Onco_education/       ← свой репозиторий, свои ветки, свои PR
~/code/следующий-проект/     ← свой репозиторий, свои ветки

~/.claude/CLAUDE.md  ──симлинк──▶  ~/ai-setup/rules.md
```

Проекты про этот репозиторий не знают. Ветки здесь появятся, только когда вы правите
собственные правила.

## Установка на новой машине

```bash
git clone git@github.com:Evdokimov-onco1/ai-setup.git ~/ai-setup
~/ai-setup/install.sh
```

Скрипт делает симлинки в `~/.claude/` и печатает два оставшихся шага
(Cursor User Rules и Devin Knowledge — они только через интерфейс).
Прежние файлы не затираются: сохраняются рядом с суффиксом `.backup-…`.

## Что где лежит

| | |
|---|---|
| `rules.md` | **единственный источник.** Он же `~/.claude/CLAUDE.md`, он же текст для Cursor и Devin |
| `claude/settings.json` | разрешения и настройки Claude Code |
| `claude/restore.md` | как вернуть MCP-серверы и плагины на новой машине |
| `commands/` | команды `/graph`, `/deident`, `/otkat` — работают во всех репозиториях |
| `git/` | глобальный gitignore, хук проверки на ПДн, список исключений |
| `hooks/` | сводка в начале сессии Claude Code |
| `templates/` | заготовки для новых проектов: обычный и «разбор данных» |
| `install.sh` | установка на машину |
| `new-project.sh` | подключение нового проекта |
| `copy-rules.sh` | `rules.md` в буфер обмена — вставить в Cursor и Devin |

## Как обновлять

**Скиллы сюда не входят.** Они на аккаунте claude.ai и синхронизируются сами —
правите скилл на сайте, он в тот же день работает во всех репозиториях, на вебе
и локально. Этот репозиторий для этого трогать не нужно.

То же с плагинами: `/plugin install` ставит их на пользователя, а не на проект.
Здесь хранится только *список* — чтобы восстановить набор на новой машине.

Обновляется здесь только то, что нельзя положить на аккаунт: правила, settings,
список MCP, шаблоны.

```bash
cd ~/ai-setup
vim rules.md
git commit -am "Добавить правило про конфаундеры при отладке"
git push
```

На другой машине:

```bash
cd ~/ai-setup && git pull
```

Переустанавливать ничего не надо: `install.sh` делает **симлинки, а не копии**,
поэтому `git pull` меняет поведение Claude сразу и во всех проектах.

Если правило поменялось — не забыть перезалить текст в Cursor User Rules
и Devin Knowledge: у них нет git, только копипаст. `./copy-rules.sh` кладёт в буфер.

## Как подключить новый проект

```bash
~/ai-setup/new-project.sh ~/code/мой-сайт              # обычный проект
~/ai-setup/new-project.sh ~/code/разбор-сроков анализ  # разбор клинических данных
```

Обычный проект получает `AGENTS.md` и заготовку `.ai/graph.md`.

Тип **анализ** дополнительно разводит папки: `data/raw/` (сырая выгрузка, вне git),
`data/public/` (обезличенное), `scripts/`, `out/` — и кладёт `.gitignore`, который
не пускает сырые данные в репозиторий.

Глобальные правила Claude берёт сам, копировать их в проект не нужно и вредно —
разъедутся. Всё созданное коммитится **в репозиторий проекта**, не сюда.

Репозиторий для клинических данных заводить **приватным**, даже если данные
обезличены.

## Защита от случайной публикации данных пациентов

Три слоя, все ставятся `install.sh`:

1. **Глобальный gitignore** — `data/raw/`, `*.xlsx`, `*.csv`, файлы с «выгрузка»
   и «ЭМК» в имени git просто не видит. Файлы при этом остаются на диске:
   работать с ними можно, случайно закоммитить — нет.
2. **Хук `pre-commit`** — смотрит на то, что вы коммитите. Найденное показывает
   **замаскированным** (`Си…П.`), чтобы само ПДн не утекло в лог.
3. **Сводка в начале сессии** — напоминает, если карта устарела или защита
   не подключена.

Хук **предупреждает и спрашивает, а не запрещает**. В терминале задаёт вопрос;
когда терминала нет (Claude Code, Cursor, скрипт) — останавливает коммит и печатает,
что делать, чтобы вопрос дошёл до человека, а не потерялся в логе.

### Чтобы он не задалбывал

Признаки разделены на два класса — в этом вся суть.

**Жёсткие** — СНИЛС, полис, паспорт, телефон. Останавливают поодиночке:
в учебных материалах таких строк не бывает, ложных срабатываний почти нет.

**Мягкие** — ФИО, «д.р.», адрес, номер истории болезни. Поодиночке **молчат**:
фамилия преподавателя в методичке — не персональные данные пациента. Сигналом
становится сочетание — два разных мягких признака в одном файле — или список
из десяти и более разных ФИО.

Поэтому `fos-data.json` с семью фамилиями врачей проходит молча, а выгрузка
с ФИО и датами рождения — нет.

Режим задаётся на репозиторий в `.ai/pdn.conf`:

```
режим = обычный     # по умолчанию
режим = строгий     # проекты с выгрузками: любое ФИО останавливает
режим = выкл        # заведомо без данных пациентов
```

Каждое срабатывание печатает **готовую строку**, которую достаточно вписать,
чтобы про этот файл больше не спрашивали:

```
не-проверять = fos-data.json: ФИО
```

Файлы самой проверки (`pdn.conf`, `pdn-allow.txt`, сам хук) она пропускает —
иначе ловила бы себя на словах «дата рождения» в собственных шаблонах.

### Чего в списке исключений быть не должно

`pdn-allow.txt` — только сотрудники, авторы, публичные имена. **Пациентов туда
не вписывать никогда:** список лежит в git, и перечень фамилий пациентов в нём —
ровно та утечка, которую всё это должно предотвращать. Если хук ругается на файл
с пациентами, правильный ответ — убрать файл из коммита, а не занести фамилии
в исключения.

Это страховка, а не гарантия: проверка может пропустить незнакомый формат.

## Команды

Работают в любом репозитории, потому что лежат в `~/.claude/commands/`:

| | |
|---|---|
| `/graph` | построить или обновить карту проекта с пометками `[прочитано]` / `[предположение]` |
| `/deident` | обезличить выгрузку скриптом, с разбором колонок и подтверждением |
| `/otkat` | разобраться, что произошло, и предложить один безопасный способ вернуть как было |

## Три уровня — что где

| | Глобально, один раз | В каждом проекте |
|---|---|---|
| **Claude** | `~/.claude/` — скиллы, `CLAUDE.md`, settings, MCP, плагины | `AGENTS.md` |
| **Cursor** | Settings → Rules → **User Rules**, `~/.cursor/mcp.json` | `AGENTS.md`, `.cursor/rules/` |
| **Devin** | Settings → **Knowledge**, scope «все репозитории» | `DEVIN.md`, playbooks |

Правило деления: **глобально — кто я и как со мной работать; в проекте — что это за проект.**

Cursor не видит скиллы Claude и не увидит. Мост между ними один: запускать `claude`
в терминале Cursor вместо встроенного чата — тогда локально работают те же скиллы
и те же правила, что на вебе.
