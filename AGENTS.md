# Onco_education

Читают: Cursor, Claude Code, Devin.

Здесь — **только специфика этого проекта**. Общие правила (язык, стиль, дисциплина
мышления, карта проекта) лежат глобально: Claude берёт их из `~/.claude/CLAUDE.md`,
Cursor — из User Rules, Devin — из Knowledge. Не дублировать их сюда.

Источник глобальных правил: репозиторий `ai-setup`.

## Что это

Среда кафедры онкологии ММКЦ «Коммунарка» (ординатура 31.08.57) для подготовки
восьми ФОС к аккредитации. Пять ФОС существуют, три нужно написать. Каждая тема
закреплена за врачом **с точными номерами заданий** — врач правит только свои номера.

Сайт-дашборд показывает, кто над чем работает, и ведёт в Google Drive,
где врачи пишут содержание.

## Устройство

```
index.html      сайт-дашборд, одностраничный, без сборки
fos-data.json   источник правды: темы → номера заданий → ответственный → ссылка на Drive
fos/            тексты пяти существующих ФОС
playbooks/      generate-fos.md (спецификация формата) · knowledge.md
DEVIN.md        задачи для Devin
.ai/graph.md    карта кода
```

Подробный поток данных — в `.ai/graph.md`.

## Источник правды

`fos-data.json`. «Git как база данных» — это осознанный выбор, а не временное решение.
Не предлагать завести бэкенд.

Живое состояние (прогресс, распределение) синхронизируется через Firebase RTDB —
см. карту. Обратите внимание: `README.md` и `DEVIN.md` этого ещё не описывают.

## Чего не делать

- Не подключать сборщики, фреймворки, базы данных. Сайт — один статический `index.html`.
- Не менять медицинское содержание `fos/` без указания профильного врача.
  Черновик агента всегда помечать: «требуется проверка профильным врачом: <фамилия>».
- Не менять число элементов в `themes` и не переименовывать ключи ФОС.
- Не менять нумерацию заданий в существующих ФОС — кафедра решила оставить как есть.
- Не переписывать `fos-data.json` по своему усмотрению: только по присланной версии
  или по явной задаче.
